# Аудит контрасту Personal / Business

**15 жовтня 2026. Висновок: Block — є підтверджені проблеми контрасту активного UI.**

Це аудит стану робочої копії на момент збережених знімків. Під час самого аудиту кольори та компоненти продукту не змінювалися. Помилки нижче не слід вважати регресіями останніх змін без окремого порівняння з Git.

## Охоплення

- 62 групи каталогу, усі 179 URL-станів **у кожному** профілі: 358 унікальних комбінацій стан/профіль.
- Серед них — 13 повних банківських екранів та redirect для Personal і Business, primitives, банківські віджети, діалоги, sheets, меню, Tooltip, HoverCard, Popover, Drawer.
- Додатково: справжні pointer-hover та клавіатурний focus усіх шести варіантів Button, клавіатурний focus у Popover і Drawer, шість типів відкритих toast-повідомлень, контекстне меню та тексти самої галереї.
- 492 DOM-знімки; 6476 попередніх вимірювань текстів, placeholders, значень полів, SVG-фарб, меж і focus-outline. Це кількість вимірювань, **не** кількість незалежних компонентів або підтверджених дефектів.
- Окрема растрова перевірка восьми платіжних карток: default / virtual / frozen / private у двох профілях.

Кольори взято з `getComputedStyle()` у живих iframe. Розрахунок використовує відносну яскравість sRGB, alpha-композицію й прозорість предків; підтримує також обчислені OKLab/OKLCH та `color(srgb ...)`. Фон зображення/градієнта не підмінявся звичайним CSS background-color. Такі рядки позначені для окремої перевірки. Початкові вимірювання під час fade-in не використовуються як підтверджені дефекти; ключові попапи повторно знято в сталому стані.

Для звичайного тексту застосовано 4,5:1, для великого тексту — 3:1. Необхідні для розуміння іконки, межі та індикатори стану перевіряються відносно суміжних кольорів за порогом 3:1. Декоративна рамка текстової кнопки не автоматично зобов'язана проходити 3:1. Джерела: [WCAG 2.2, 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) та [1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).

## Що проходить у перевіреному зрізі

- Основні кнопки: білий на `#0034B8` — **9,62:1**; чорний на `#CC5C00` — **5,10:1**. Бізнес-колір не треба замінювати заради цих двох пар.
- Реальні hover/focus Button перевірено окремо від зафіксованих fixtures. Додаткових підтверджених провалів тексту в шести варіантах не виявлено. Hover використовує `brightness(.96)` для primary: його вплив враховується окремо від computed background-color; після множника .96 розраховано **9,21:1 Personal** і **4,75:1 Business**.
- У повторно перевірених сталих Dialog, AlertDialog, Popover, HoverCard, Tooltip, DropdownMenu, Transfer, Receive та Exchange активні тексти й placeholders не дали підтверджених провалів. Результат не поширюється на непройдені внутрішні кроки кожного фінансового сценарію.
- Службові однотонні іконки у перевірених активних контролах не дали окремого підтвердженого дефекту. Низькі значення SVG-сітки, декоративної стрілки Tooltip та multicolour chart paints не трактуються як дефекти службових іконок.
- Frozen-картки дали достатній запас у растрових пробах. Звичайна Personal badge — **приблизно 4,53:1** у glyph-пробі: граничний результат без запасу, потребує повторної перевірки на інших розмірах. Смуги навколо текстового line box можуть бути світлішими за фон безпосередньо під glyphs, тому їхні нижчі коефіцієнти не оголошено точним провалом тексту.

## Disabled

У вимірюваннях є 223 рядки з DOM disabled / aria-disabled / data-disabled. Частина пов'язаних labels також має opacity, задану стилями неактивного контролу. Неактивні компоненти звільнені від нормативних контрастних порогів 1.4.3 і 1.4.11; нижчі значення не записуються як WCAG-помилка. [Пояснення W3C](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html#inactive-user-interface-components).

Primary disabled Button має спеціальну непрозору пару `--bank-disabled-ink` / `--bank-disabled`: **5,31:1** у двох профілях. Інші disabled Button variants мають приблизно **2,06–3,23:1**. Це рекомендація щодо читабельності, не обов'язкове порушення. Висновок не дозволяє застосовувати disabled-виключення до read-only тексту, який користувач повинен читати.

## Межі висновку

Це перевірка актуального каталогу й перелічених живих взаємодій, а не повна WCAG-сертифікація продукту. Не підтверджено кожну комбінацію даних, locale, розміру екрана, вкладеного кроку сценарію або кольорів у сторонніх raster assets. Повний перебір hover/focus кожного нащадка кожного компонента не виконувався: каталог охоплює застосовні fixtures, а справжні pointer/keyboard стани перевірено на шести Button variants і зазначених портальних контролах. Темні та системні high-contrast режими не входили в цей зріз Personal/Business.

Градієнтні картки перевірено на захопленому розмірі 384×242 CSS px. Піксельна інтерполяція дає локальну оцінку; зміна масштабу або розташування тексту потребує нового знімка. Для Virtual product-name проби поблизу line box також граничні/нижчі за 4,5:1; потрібна перевірка точного фону під glyphs перед окремим вердиктом для цього рядка.

## Наступна зміна: білий текст Business-дій

Після цього аудиту, за прямим запитом користувача 15.10.2026, `--bank-action` Business змінено на `#B85000`, `--bank-action-ink` — на білий; `--primary` тепер посилається на action-role. Нова пара має 5,02:1; hover `brightness(.96)` — 4,91:1. Бренд `#CC5C00` та його чорний foreground для identity-avatar збережено. Це окрема зміна основної дії, яка не означає автоматичного виправлення інших пунктів звіту.

У браузері підтверджено колір Button у галереї та Dialog, перевірено 13 Business-екранів: основні активні Button мають темнішу заливку й білий текст; білий текст на початковій бренд-заливці не виявлено. Personal Button лишився `#0034B8` / білий.
